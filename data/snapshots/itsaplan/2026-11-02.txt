 Who it&#x27;s for
 Every team can hand work to agents now
 Coding agents came first. On the same board, agents also take requests, drafts and status reports, each under its own name, and a person approves the result.
 Background coding agents
 Software teams
 Assign an issue to Claude Code or Codex the way you assign it to a person, and review the pull request in the same issue.
 AI content ops
 Content and marketing
 A first draft of each article is ready every morning, so editors spend their time on editing.
 Multi-agent orchestration
 Agent networks
 Many agents work from one board and hand work to each other through linked issues. A person approves the result.
 Client portals
 Agencies and studios
 Each client follows its own project, an agent writes the weekly status, and inviting clients costs nothing.
 AI help desk
 Support desks
 Requests from a web form land in one queue, sorted by an agent before anyone opens them.
 Social media automation
 Social media
 An agent drafts the week&#x27;s posts every Monday. You approve each one on the calendar, and a webhook sends it to the tool that publishes it.

 2.0 · Delegate
 Build strong AI agents
 Write down how your team does a job, choose the tools an agent may use, then hand it an issue. It runs on your own key with any provider, or through Claude Code on your machine. We don&#x27;t sell AI credits.
 In the app
 Hosted
 The no-code way. Set it up in the app and it runs on your instance.
 Model Any provider, on your own API key. You keep full control of the model and the spend. Pick it per agent. 
 Skills Loads them when it needs them. Write one, upload a file, or import a set from GitHub. 
 Tools Tick what it may do with issues, and which outside tools it may call. 
 On your machine
 External
 Runs where the code already is.
 Where Your machine or your VPS. One command starts the runner. 
 Tools Your CLI, your config, your logins, or a command you write yourself. 
 Chats Every chat has a session id. Continue it in your own terminal.

 4.0 · Plan
 Group issues into goals you can track
 Link issues from anywhere in the project to one initiative. It counts what is done and puts it next to the time gone, so you can tell early whether the date will hold.
 Progress you never update by hand
 The percentage counts the issues under the goal by state, so it changes as soon as someone moves one.
 Every goal has an owner
 Each initiative has an owner, a priority and a health status. Its issues stay on the team board and show up here too.

 7.0 · Integrate
 A REST API and MCP server, out of the box
 Everything the UI does, the API does. Point Claude Code, Cursor, or your own client at /mcp and over 200 API routes become tools it can call, with the access of the key it uses.
